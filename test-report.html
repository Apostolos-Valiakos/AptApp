Where the tests are weak

Many survivors are harmless, such as console messages or icon names. These are the ones that matter, most important first:

  • Resizing an appointment as a shop role has no test (resizeCard in SchedulerView.vue), including going back after a refusal.
  • A dragged appointment's other fields are barely checked: its new duration, new staff member and overtime flag, plus Ctrl + drag moving all its parts, and the "appointment deleted elsewhere" conflict (dropCard and updateAppointment).
  • Saving and loading discounts has no test: discountFromAppointment and discountPayload in discount.ts, which decide what is sent to the server.
  • The calendar's background work is untested: downloading ahead for offline use (prefetchAround), refreshing time off and working hours, reloading after a sync, and offline fallback for staff and working hours.
  • The shop-wide cash lock at login isn't checked (login in auth.ts).
  • The in-app redirect to the home page isn't tested (the first check in the page guard).

Running it

npm run test:mutation
# takes about 8 to 11 minutes; open reports/mutation/mutation.html for every result
  • stryker.config.json lists the files and line ranges to test.
  • For .vue files, Stryker counts line ranges from the start of the script block, not the start of the file. In SchedulerView.vue, subtract the line number of <script setup> from the file's line number. These ranges need updating when the file changes a lot.
  • The report folder and Stryker's temporary folder are in .gitignore. Server code isn't covered by Stryker.

npm test                   # everything, now including the new tests
